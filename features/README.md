## Status and profile semantics

- Every production scenario owns one repository-unique `@REQ-*` ID, at least one requirement classification, and exactly one effective status.
- A status is a product implementation declaration, not a summary of every supporting test result. Focused fixtures, adapter tests, or protocol probes do not change it.
- `@implemented-and-validated @web` scenarios run through the Playwright web profile. The current selection contains two scenarios: `REQ-WEB-001` and `REQ-LAYOUT-WEB-001`.
- `@implemented-and-validated @desktop @native-gui` scenarios run through the explicit `desktop/tauri-webdriver` profile. The current selection contains exactly two scenarios: `REQ-DESKTOP-FILE-OPEN-001` and the bounded deterministic `REQ-REFACTORKIT-JAVA-IMPORT-002`, with release/no-bundle native GUI E2E evidence rather than provider-package, application-package, Wayland, other-operating-system, or broader-confinement evidence.
- `@implemented-not-e2e-validated @desktop` scenarios run through the deterministic `desktop/tauri-harness` aggregate. It currently selects two scenarios, `REQ-LAYOUT-DESKTOP-001` and `REQ-REFACTORKIT-JAVA-IMPORT-001`, but provides no native GUI/E2E evidence.
- `@not-implemented` scenarios are excluded from implemented aggregates. The current count is two: `REQ-REFACTORKIT-TS-001` and `REQ-REFACTORKIT-TS-002`.
