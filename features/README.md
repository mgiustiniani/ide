## Status and profile semantics

- Every production scenario owns one repository-unique `@REQ-*` ID, at least one requirement classification, and exactly one effective status.
- A status is a product implementation declaration, not a summary of every supporting test result. Focused fixtures, adapter tests, or protocol probes do not change it.
- `@implemented-and-validated @web` scenarios run through the Playwright web profile. The current selection contains two scenarios: `REQ-WEB-001` and `REQ-LAYOUT-WEB-001`.
- `@implemented-and-validated @desktop @native-gui` scenarios run through the explicit `desktop/tauri-webdriver` profile. The current selection contains exactly seven scenarios/198 steps: `REQ-LAYOUT-DESKTOP-001`, `REQ-DESKTOP-FILE-OPEN-001`, the bounded deterministic `REQ-REFACTORKIT-JAVA-IMPORT-002`, the UI-only missing-Steam machine Settings `REQ-XCOM2-MACHINE-SETTINGS-MISSING-STEAM-001`, the recognition-only `REQ-XCOM2-MODULE-ACTIVATION-001`, the explicitly configured recognition-only `REQ-XCOM2-MODULE-CONFIGURATION-ACTIVATION-001`, and the safe configuration diagnostic `REQ-XCOM2-MODULE-CONFIGURATION-DIAGNOSTICS-001`. XCOM activation and diagnostic evidence is bounded to the actual sandbox filesystem and production Linux X11 Tauri release/no-bundle WebKit DOM at an asserted 1440x900 viewport, with its ADR 0007 Option A semantics, scoped project-input no-write and disclosure checks, and exclusions retained. Layout evidence is limited to the release/no-bundle Linux X11 WebView DOM at an asserted 1440x900 viewport, with no OS decoration, package, Wayland, DPI-behavior, drag-resizing, restart-persistence, or optional-right-sidebar claim. The other native requirements retain their separately stated evidence boundaries.
- `@implemented-not-e2e-validated @desktop` scenarios run through the deterministic `desktop/tauri-harness` aggregate. It currently selects `REQ-REFACTORKIT-JAVA-IMPORT-001`, `REQ-XCOM2-MACHINE-SETTINGS-001`, and `REQ-XCOM2-PROJECT-FOUNDRY-001` for exactly three scenarios/84 steps and provides no native GUI/E2E evidence. The XCOM machine Settings lifecycle is separate from XCOM project/module activation and carries no native GUI, real IPC, live Steam, real filesystem, package, bundle, or installer claim. Project Foundry retains its deterministic harness-only boundary and all native chooser, application-package, distribution, Windows, Apply, creation/write, and build exclusions.
- `@not-implemented` scenarios are excluded from implemented aggregates. The current count is two: `REQ-REFACTORKIT-TS-001` and `REQ-REFACTORKIT-TS-002`.
