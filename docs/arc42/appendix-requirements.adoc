== Governance

The `.feature` files are the authoritative declarations for stable requirement IDs, classification, tags, scenarios, and declared status. This appendix records those declarations alongside independently observed validation:

* one scenario must own one repository-unique `@REQ-*` ID, at least one requirement classification, and exactly one effective status;
* declared status and observed validation are separate fields: discovery, parsing, execution, supporting implementation, or inspection never silently changes a feature tag;
* supporting Spec, contract, adapter, metadata, or UI tests do not establish full Story GREEN;
* actor/stakeholder and capability wording is derived from the feature narrative and scenario, without inventing a more specialized role;
* browser, fixture, desktop/Tauri, native GUI, and packaged-daemon evidence remain separate target/mode fields; and
* `ARC42.md` remains the integrated mutable architecture-status narrative. Gherkin, this appendix, test output, ADRs, C4 views, and upstream release artifacts remain bounded evidence sources.
