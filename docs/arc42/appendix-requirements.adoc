== Governance

The `.feature` files are the authoritative declarations for stable requirement IDs, classification, tags, scenarios, and declared status. This appendix records those declarations alongside independently observed validation:

* one scenario must own one repository-unique `@REQ-*` ID, at least one requirement classification, and exactly one effective status;
* declared status and observed validation are separate fields: discovery, parsing, execution, supporting implementation, or inspection never silently changes a feature tag;
* supporting Spec, contract, adapter, metadata, or UI tests do not establish full Story GREEN;
* actor/stakeholder and capability wording is derived from the feature narrative and scenario, without inventing a more specialized role;
* browser, fixture, desktop/Tauri, native GUI, and packaged-daemon evidence remain separate target/mode fields; and
* `ARC42.md` remains the integrated mutable architecture-status narrative. Gherkin, this appendix, test output, ADRs, C4 views, upstream release artifacts, and legacy `PLAN.md` remain bounded evidence sources.

|Actor / stakeholder
|A TypeScript developer using an authorized desktop workspace. The Business Need also names TypeScript and JavaScript compiler errors as the bounded language scope.

|Request exact, non-writing compiler diagnostics for the current authorized source snapshot; reject stale workspace/session/snapshot results; present readiness honestly; reuse Problems and Monaco diagnostics without fallback output or a TypeScript-specific panel.

|Scenario
|_View trustworthy compiler diagnostics in the existing IDE problem surfaces_

|link:../../features/refactorkit/typescript-compiler-diagnostics.feature[`features/refactorkit/typescript-compiler-diagnostics.feature`], scenario beginning at line 6

|Tags
|`@desktop`, `@REQ-REFACTORKIT-TS-001`, `@functional-requirement`, `@non-functional-requirement`, `@not-implemented`

|Declared status
|`@not-implemented` — copied from the feature source. Passing support tests and expected RED Story evidence do not promote it.

|Intended validation target
|Desktop/Tauri Story BDD through the explicit `desktop` profile. The target is the existing desktop composition, qualified native RefactorKit request boundary, existing Problems experience, and Monaco diagnostics; it is not a browser-only or TypeScript-specific panel target.

|Completed supporting metadata evidence
|On 2026-07-14, 113/113 focused contract, Tauri-adapter, and UI tests passed. They prove strict schema-v1 operation metadata preservation/rejection, all seven required fields (`operation`, `stability`, `evidence`, `mutationAuthority`, `backend`, `runtime`, `extensions`), nested cloning/immutability, and runtime-before-extensions presentation. Rust canonicalizes adapters, operations, and extensions after validation, so the Language Lab receives deterministic canonical order rather than provider-supplied order. It labels discovery metadata separately from workspace/toolchain/session readiness.

|Completed supporting Spec evidence
|The readiness Spec passed 27/27 cases. The pure policy can authorize one immutable request bound to TypeScript, authorized workspace/generation, semantic session, snapshot hash, provider version, and exact operation backend; it refuses stale, ambiguous, incomplete, mismatched, unsupported, or unqualified evidence before invocation. This is policy evidence only: the Spec starts no daemon, receives no real diagnostic result, and renders no Problems or Monaco marker.

|Expected meaningful RED evidence
|On 2026-07-14, focused diagnostics Story execution produced the required meaningful RED: 1 failed scenario, 5 passed steps, and 6 skipped steps. The independent full quality rerun retained that expected failure. The fixture entered through desktop adapter composition and the RefactorKit Status controller, preserved the exact advertisement, and then reached `run_refactorkit_diagnostics`. The current adapter invoked it with no qualified request (`{}`) instead of the required language/workspace/generation/session/snapshot/provider/backend fields. The failure is at the intended missing integration boundary rather than at feature discovery or stale metadata shape.

|Native GUI / full Story evidence absence
|No native Tauri WebView or packaged-daemon GUI run has completed this scenario. No run has shown exact RefactorKit TypeScript diagnostics for the current editor snapshot in both Problems and Monaco. The expected RED is not full Story GREEN, and the supporting jsdom/Tauri-invoke fixture is not native GUI evidence.

|Upstream immutable `v0.6.2` evidence
|An isolated packaged daemon whose 424 source blobs matched immutable tag commit `110b605` with zero mismatches passed Java preview/no-write, discard, exact apply, and byte-for-byte rollback smoke under OpenJDK 21. This validates that isolated package/import path only. The globally installed runtime, launcher, and checksum still report `0.5.0-SNAPSHOT`; no global `v0.6.2` promotion is claimed.

|Operation stability / unsupported scope
|RefactorKit `v0.6.2` TypeScript/JavaScript operations are not universally stable. Structural outline and identifier search are working provider foundations, not IDE capabilities. Semantic definition, references, workspace symbols, and diagnostics are experimental provider foundations; semantic rename is experimental proposal-only. Format, move, organize imports, change signature, extract, and inline remain unsupported for TypeScript/JavaScript. All unintegrated operations remain unscheduled TODO and are not simulated.

|Open upstream compatibility blockers
|The daemon diagnostics response drops start character and end range; lacks request/result workspace, generation, session, and snapshot authority correlation plus exact compiler attestation; does not define saved/unsaved snapshot semantics; advertises the TypeScript LSP backend/runtime rather than the separate exact compiler-diagnostics backend; advertises 10-second/64 MiB LSP limits while the compiler bridge uses 30 seconds/8 MiB; and can encode readiness or tool failure as ordinary diagnostics. These prevent trustworthy existing-surface projection.

|Decision status
|`WAIT_FOR_UPSTREAM_PROTOCOL_FIX` — option A is selected until further notice. This is a reversible temporary product decision, not a permanent ADR. The IDE will not implement a Problems-only saved-disk fallback and will not fabricate approximate Monaco line markers. The user may explicitly revise the decision.

|Upstream conditions before resumption
|Upstream must provide (1) exact bounded UTF-16 ranges or explicit enforceable precision, (2) request/result authority correlation, (3) exact compiler attestation, (4) explicit saved/unsaved snapshot semantics, (5) structured readiness/refusal/failure outcomes, and (6) compatible advertised/observed runtime and response bounds.

|Decision status

|Roadmap effect
|The requirement is parked outside the active roadmap. Deterministic support remains evidence, but no IntelliSense/JDT LS expansion or RefactorKit navigation milestone is scheduled from it.

== Reconciliation and Migration Status

The web characterization slice is independently passing for its explicit web/Playwright validation mode. The RefactorKit diagnostics requirement has completed metadata/readiness-policy support and an expected meaningful RED, but remains declared `@not-implemented` with no native GUI/full Story GREEN. The separate symbol-navigation requirement has completed implementation and deterministic 18/18 desktop Story evidence, but remains declared `@not-implemented` and blocked under option A: real immutable `v0.6.2` evidence violates its no-workspace-write clause, aggregate desktop Story support is absent, and no packaged GUI/E2E evidence exists. Both TypeScript/JavaScript requirements are parked outside the active roadmap. Structural outline/identifier search remain provider foundations, while TypeScript references/rename and general Java refactoring remain provider-foundation or IDE TODO according to observed support. Announced search operations with optional JSON remain TODO until a released strict typed bounded versioned machine-readable JSON contract or equivalent daemon DTO carries structured errors, truncation, authorized locations, and request/result correlation and passes immutable real acceptance evidence; human stdout is never an IDE protocol. These results confirm neither the inherited Chapter 1 goals nor complete BDD migration and do not supersede broader frontend, Rust, Java, RefactorKit, XCOM, and GUI evidence boundaries.

Legacy `PLAN.md` remains a migration input and causes the documentation validator's expected migration warning. Its architecture content still needs classification into ARC42, ADR, specialist evidence, or removable history before strict bdd-ts admission; no requirement is promoted merely because legacy implementation, support code, upstream code, or plan text exists. No final bdd-ts migration admission is claimed while that legacy source and the desktop aggregate Story and packaged GUI/E2E gaps remain.
